## 2. What is new since 2026-10-05

1. **BLOB in the controlled environment** (`docs/blob_controlled_integration.md`). The released code reproduces the
   paper's Table 3 within 0.02 CTR points; the PyTorch port replays the authors' TensorFlow graph step by step. Given
   the logger's own vectors as its source, the published BLOB is the weakest model-based learner at 25k.
2. **BLOB's catalog-size prior** (`docs/blob_prior_calibration.md`). In the released code every entry of BLOB's
   correction has prior variance s+(w_b)²/P: 35–108 times tighter in our catalogs than at the paper's P = 100.
   Computing L at a fixed reference size (pre-registered; P₀ = 10 chosen on tuning seeds) makes BLOB-Pnorm-NQ level
   with OPC and just below CausE-cap.
3. **What each arm optimizes** (`docs/training_objectives_audit.md`). An audit of the executable objectives of BLOB-NQ,
   CausE-cap at ρ = 0 and OPC. CausE-cap at ρ = 0 is a penalized likelihood in OPC's class (its L2 term and CausE's
   L1 tie anchor toward the source without restricting the class); OPC maximizes a harmonic-weighted DR value with no
   explicit penalty; BLOB is variational Bayes with a P-dependent source prior. Two report statements were corrected
   (§4 below).
4. **A correctness review of the live code, and its fixes** (§5). Rerunning, resuming and extending a run are now
   idempotent: `--skip-completed` checks the exact labels, train sizes and settings, and no run repeats or drops rows
   (README, "Rerunning, resuming and extending a run").

Reviewed: the study runners and every arm (OPC, no-propensity, DM-only, tempered logger, CausE, BLOB), the simulator,
the reward models and DR scoring, the class oracles and pick diagnostics, the CausE, BLOB and revalidation analyses,

**Found and fixed while fixing these** (the same workflows):
- **Rows dropped on a partial rerun.** A run of a subset of arms rewrote `summary_metrics.csv` with only those arms,
  plus the cached OPC and no-propensity rows, re-tagged with the new invocation's settings. This dropped the DM-only,
  tempered-logger, CausE and BLOB rows; `trials_long.csv` likewise lost DM and tempered-logger trials. Now every file of
  the folder is merged: a run replaces exactly the (label, train size) rows it produces.
- **`run_meta.json`** was overwritten by each invocation. It now accumulates `labels`: each label's arm, configuration
  key, code commit and time, with the settings of every key.
- **`failures.csv`** stayed after a successful resume. It now lists the latest invocation's failures only.
- **Appending a log under a different header shifted values into the wrong columns.** The file is now rewritten with
  the union of the columns.
- **A row kept by a merge could change in its last digit** (pandas' default float parser does not round-trip), found by
  the CPU suite. Files the runners rewrite are now read exactly.
- **The cached-runs fallback** took an interrupted attempt's row. It now takes the last row.

**Before and after** (one toy condition, the same sequence of commands; `tests/test_resume_idempotence.py` covers it):
